LAN 可读的真实成本不是多一个端口，而是信任语义的改变：LAN 不是信任边界。它含携毒笔记本、访客网段、被 VPN 扩大的名义局域网。放 LAN 等于把审议立场、纪要、注解的机密性从「隧道内」降为「局域网内」。但收益也真实：现隧道每查看者需 SSH 凭据，移动端与随手查看皆不可用；放开 LAN 是协作方向的实际解绑。第一步做数据分级：链上无密钥、无 pins，机密性低，高价值属性是完整性，且已由两条硬不变量守护。分级成立则开放只读可接受，但要白纸黑字写明这是主动取舍，不是疏忽。

隔离的可操作性：拆进程易，拆数据通路难。读面若经写面 loopback API 中继读数据，被攻破即成写面代理，是新增写路径，违反 fail-safe。正确形态是读面以独立低权 OS 用户、只读挂载直读链存储，不持有、不经过写面任何接口；逐条验证读面无写 fd。

边界形态：独立只读 HTTP 进程，显式绑定 LAN 接口地址（非 0.0.0.0、非 WAN 接口），严格校验 Host 头拦 DNS rebinding；无状态、无 cookie、仅纯 GET 读端点，其余一律 404/405 默认拒绝。运维面最小化：单进程、读文件、无 DB，配监控与重启策略。

认证取舍：默认不做应用层认证。受众裁定即「整个 LAN」；为只读查看器配 per-viewer 认证，运维成本高而防护增益趋零，对既定威胁无益。URL token 会经日志、历史、截图泄漏，属安全剧场。若日后机密性分级升高，便宜杠杆是网络分段（VLAN/防火墙限源），而非应用层认证。fail-safe：任何歧义即拒绝，读面永不成写面跳板。
