## 0. 定位：为什么这是一份方向材料而不是一份任务清单

Owner 于 2026-08-19 给出 AOS 新 MVP 的五条目标，并在同一会话中作出两条澄清与一条处置裁定。这些合起来**不是给现有底座加功能，是换真值**：今天的 AOS 是治理链的驾驶舱——它的前端读的是 workflow 链的投影，它的 `verify` 主体证的是"我和链的关系正确"，它的写面只有四个动词且人没有写路径。新目标要求它成为**自有真值的独立产品**。

按《方向与轨道取舍公约》的触发阈值，这一变更多点命中（详见 §Q1），属方向题，须在动手前先行裁定，不得留给执行期撞见。

## 2. 方向主张（Owner 已裁，本材料据此展开）

**五条目标**（2026-08-19）：

1. 实现 Jira 与 Confluence 级功能，参照 workflow 已实现的功能面，但**与 workflow/helper 零依赖关系**。
2. 可通过 **k3s 单机部署**。
3. 提供**通用标准的 API 与 MCP 服务**。
4. 允许对现有底座进行**任何程度的破坏性更新**。
5. **单项目自主运行、人手工即可完成全部项目管理**。

**两条澄清**（Owner 原话与其含义）：

- **"不依赖任何第三方内容"** ＝ 单项目自己就能自主运行、手工也能管理项目；**并非禁止引入第三方环境库**。库的引入回归《现成方案优先与外采审查公约》的常规流程。
- **"平台层职责借住在 AOS 仓里是错误的"** ＝ AOS 老老实实实现自己的工单管理与知识库，**不承担任何工作流框架职责**。

**一条处置裁定**：平台器官的去向选 **B——有记录地退役，不搬家**。

由此导出两条本材料全程遵守的红线：

- **零 workflow 前提。** 本材料不含任何"与 tcrn-workflow 集成"的设计。产品在两个仓不存在时行为不变，且这一点由 §分期一期的 `absence:proof` 变成观测而非声明。
- **AOS 永不再承担平台职责。** 这条以后是判断新需求该不该进 AOS 的判据，而不只是这一次的清理理由。

## 3. 开工前必须先清的三道闸

这三道闸都不是产品设计问题，而是"这次重建是否有合法起点"的问题。**在它们清掉之前，重建的不可逆动作不得执行**（《方向与轨道取舍公约》第 1 条：未答之前不得在该方向下执行不可逆动作）。

### 闸一：相位一是否已关闭（最硬的一道）

《依赖方向与集成边界公约》第五节逐字规定相位次序，并写明"**相位一期间，AOS 只做门诚实性维护（让门量的东西与实况一致），零特性开发**"，且相位一"须有**可测的完成判据**；判据不成文，这个相位就关不上"，并点名 `TCRN-CROSS-INIT-020`——收口判据不成文，收完又开——为前车之鉴（复核：`docs/dependency-direction-and-integration-convention.md:64-71`）。

AOS 重建是相位二工作。**这道闸未清，重建无从合法开工。** 需要一条 cross-project 裁定：宣告相位一已闭并附成文的可测判据，或显式修订相位次序。

### 闸二：外采公约的裁可状态

《现成方案优先与外采审查公约》首部状态行仍写"状态：交付草案。公约文本的效力以 Owner 裁可为准；裁可后在本行登记裁可日期"，**实测未登记任何日期**（复核：`docs/sourcing-and-vetting-convention.md:7`）。该公约自述在裁可落地前"按建议而非授权对待"。

后果是归道级的：按《方向与轨道取舍公约》"引不出具体裁定就不算有支撑，回 OWNER-NOW"的规则，**未裁可则本次全部外采条目都要上 OWNER-NOW，而非 AGENT 自决**。重建要一次性引入 HTTP 框架、schema 库、数据库驱动、Markdown 渲染器、MCP SDK、HTML 解析器等多条依赖，逐条上 OWNER-NOW 是可观的 Owner 负担。

### 闸三：存储选型是否已被既有裁定占位

**这是本次检验最重要的发现，且与两份候选设计的假设直接冲突。**

链上存在一条 2026-08-06 的 Owner 裁定，选定 Postgres 并把 SQLite 记为**被拒方案**，被拒理由逐字为"Owner 判其不承载未来协作功能写入"（实测可见于 `apps/web/src/cockpit-data.generated.ts` 内的链投影文本）。对应 ADR 为 `tcrn-workflow/docs/adr/0004-postgres-storage-backend.md`，状态 accepted。

**但它的主语必须看清。** ADR 0004 的对象是**受治工作区（五条链）的存储后端**，其上下文是 `MIN-063`/`MIN-064` 的 D1–D5′：D1"AOS 成为引擎前的唯一读写门面，与链同驻"、D3′"VM 上单个 PostgreSQL 实例绑回环、仅经 SSH 隧道可达、每链一个 schema"。**这些前提今天全部被推翻**：AOS 不再是引擎门面（零依赖）、不再与链同驻、VM/SSH 姿态退役、部署形态改为 k3s 单机。

因此判断如下，**这是一个需要 Owner 明裁的归属问题，不是我可以自行认定的**：

- 那条裁定的**主语**（链后端）已随姿态更替而与新 AOS 无关；
- 但那条裁定的**理由**（"SQLite 不承载未来协作功能写入"）是一句关于产品能力的判断，而新 AOS 正是那个协作产品——**理由直接转移，不能当作与己无关**。

**建议采纳 Postgres**，三条依据：理由转移且出自 Owner 自己对协作写入的判断；k3s 单机下 Postgres 以同一份清单内的 StatefulSet 交付，随部署包一起起来，不构成"运行期依赖外部服务"，与目标 5 相容；`pg` 驱动已在本平台走过四门审查。**若 Owner 把目标 5 读作"一个容器一个文件"，则该建议不成立，须在存储工作开始前推翻，而不是在验收时。**

## 4. 必答段

### 方向与轨道

本 INIT 遵循《方向与轨道取舍公约》（`docs/direction-and-tracks-convention.md`，`TCRN-CROSS-INIT-012` / P7）。

#### Q1 触发判定

逐项对照触发阈值，**四行全中**：

- **难以逆转**：数据库 schema 与领域模型（取代链投影的自有存储）；可变性语义（可编辑/可重开 vs 追加不可改）——这一项一旦定下会渗进每个 API 与每一屏，是全案最难回头的一处。
- **涉及外部消费者或租户**：对外 REST/OpenAPI 契约与 MCP 工具契约，一经发布即有人建在上面；认证与权限模型同理。
- **会封死替代架构**：存储引擎选型、单表 `kind` 列 vs 多表分型的层级模型、UI 与 API 同源同权的强制机制。
- **状态与真值的落点选择**（2026-07-30 增行）：工单与知识库的真值从此住在 AOS 自己的库里，由 k3s 单节点常驻服务，备份从集群内 CronJob 发起。这是本次最直接命中的一行。

判别句检验："这个选择若在三个月后被推翻，要动的是代码，还是已经落地的数据、已经发出去的契约、以及别人已经建在上面的东西？"——**后者**。触发成立。

#### Q2 备选轨道与被拒方案

**备选轨道数：3（另有 2 条在更早层次被拒）**

**保留：轨道 A——干净内核 + 按屏纵切分期**（推荐，三份独立候选经三视角评判后的合成体）。以自有 Postgres 存储与单一命令注册表为地基，每一期交付一组完整可操作的屏，UI/REST/MCP 三面共用同一注册表并由门强制同权。

**被拒 B：最大化沿用现有 `packages/domain` + `packages/db`**——理由：现有代码承载的是"别人真值的只读驾驶舱"形状，这个形状在类型、store、脱敏层与测试里，沿用即把旧心智模型一并搬进新产品；且其领域层三分之二是治理仪式，三个分型接口加手工维护的六处子 id 数组是既有漂移源，加一种 kind 就要再加一个接口。

**被拒 C：纯分层重写（先建完整层，后接屏）**——理由：本项目真正稀缺的资源是 Owner 的评审注意力（前端车道止步 `pending-owner-acceptance`，需 Owner 的眼睛）。分层重写把这份注意力集中到一次终局评审上；而本仓自己的历史正是反证——十七道标记门与六十余条断言全绿的那天，Owner 打开应用当场找出六处缺陷。

**被拒 D：只加只读面、不做写路径**（承 CONF-013 已拒项）——理由：不满足"可读**可写**"与"人手工可管理"。

**被拒 E：维持链驾驶舱形态、在其上加功能**——理由：Owner 已裁定 AOS 不承担任何平台职责；且 `TCRN-CROSS-INC-234`（三处引擎 MCP facade 引用随 v0.11.18 退役而红）已证耦合的代价。

#### Q3 每条保留轨道三件事

| 轨道 | 适用性谓词（具名受益者） | 运营成本归属 | 日落或复审条件 |
| --- | --- | --- | --- |
| A（独立工单+知识库产品） | 至少一位**人类**成员需要在无 AI 参与的前提下手工完成全部项目管理（Owner 本人起步），且 agent 作为可选加速器其写入可归属、可审 | AOS 仓 / Owner：k3s 单节点运维、Postgres 备份与恢复演练、身份与令牌管理、**以及 AOS 回归 `product-gates` 后每次落 done 前 26 小时内须有一次真跑绿判决的持续义务** | 每季复审重答谓词。谓词不成立（无人类日常使用该系统管理项目）即收缩回只读或停止投入 |

#### Q4 接缝方案

- **UI 与 MCP 同源同权接缝**（本案第一不变量）：UI 只以真实 `<form method="POST">` 提交变更，服务端按 `Accept` 协商返回 303 或 JSON——UI 因此在构造上就是 API 客户端，且无 JavaScript 亦可工作。四道门守住它：注册表**集合相等**（注册表 id ≡ OpenAPI operationId ≡ MCP 工具名，双向漂移皆红，豁免名单 MVP 期必须为空）；无侧门（只有 kernel 可 import store，Web/HTTP/MCP 层皆不可）；**表单回放**（启动真服务、GET 每条声明路由、解析 HTML 取出每个 form 的 action 与具名输入、原样 POST 回去并断言状态变化）；**纯人类通关**（数据库中零个 agent 主体、MCP 服务不启动、关闭 JavaScript 走完整流程）。
  - 明确拒绝的做法：在构建产物里搜命令名字符串。那正是 `INC-021` 的失败形状（三十二条占位路由各答 200 且字节相同），检的是标记存在而非控件可用。
- **可变性接缝**（三层，且分层本身就是设计）：
  1. **可变 + 版本 + 前像**：工单、页面、项目、主体、标签、关联、看板、保存视图、评论。每次变更须带 `If-Match`/`expectedVersion`，不匹配返 409 并回带当前行；每次变更写一行保存**旧值**的修订记录。
  2. **追加不可改（触发器强制）**：活动事件、三张修订表、清除日志。
  3. **本性不可改，以取代更正**：审议立场、纪要、门决议、决策。更正是新行加 `supersedes_id`，UI 把被取代者划线并链到后继，**被驳倒的立场留在记录上**。
  - 这一层的价值全部在于"某个具名的人在某个具名时刻说了某句具体的话"，回溯编辑会摧毁它唯一的性质。**它被限定在这一层而不是全域**——把追加不可改的语义套到整个产品，正是现有底座作为产品不可用的原因。
- **审计与可删除接缝**：活动事件只存执行者、动作、对象、时刻、策略版本与**变更的字段名**加指向修订行的外键，**从不存值**；值只住在修订行里，修订行属第二层但有一条具名清除路径。于是常规清除删掉修订行、个人数据消失，而不可改的链条完整且从未被破坏。
- **回滚路径**：每期各自可回退；新树与旧树并存至一期删除动作发生；被拒轨道 B 的沿用点（v5 过滤模型、v6 选择语法、`StructuredComment` 分型法、12 种关联词汇、读面五条约定）以**概念移植**方式保留，不以代码依赖方式保留。

**以上每个触发项在 kickoff 纪要的决策清单中各占一条方向类条目——无既有裁定支撑者入 OWNER-NOW，须实验闭合者入 CONDITIONAL，不触发者入 AGENT。**（见 §7）

### 执行模型与交付节奏

本 INIT 遵循《交付节奏公约》（`docs/delivery-cadence-convention.md`）。

- **整合分支**：一个 INIT 一条 `feat/init<N>`，per-Epic 一个 commit；逐 Epic 本地 verify 绿 + 落链验收后推送整合分支（远端备份 + preview，生产不动）。
- **每 Epic 验收**：独立 verify + conference/minutes 落链。**不逐 Epic 合并 main、不逐 Epic 上生产。**
- **收官单次发布**：整合分支干净检出（`git worktree`）跑全量 verify → 向 Owner 呈报验收 → Owner 说 go → 单次合并 `main` → 单次部署 → 合并后 `main` 独立 verify 一次。
- **例外通道（逐项发布）**：默认关闭。**建议改为按期发布——即五个 INIT 各一次发布事件**，理由见 §5 分期；这需要显式预裁定，不能执行期临时决定。
- **敏感级纯本地**：默认关闭。
- **写新门时的世界清单**（本平台为门作者写下的最贵教训，直接适用）：每写一道门，列出它会被评估的哪些世界（工作树／干净检出／合并后的 main／别人的机器／容器内），逐个问"这里它可满足吗"。本次新增两条对应的元门：`verify-self-sufficiency`（verify 必须能在从未构建过的检出上跑——正是封闭容器构建的世界）与 `generated-encoding`（生成物内不得出现 U+FFFD——此门源于五个替换字符曾静默损坏 UI 中两个中文串）。

## 5. 架构裁定摘要与分期

### 5.1 架构（详见工作流综合稿；此处只列会改变分解树形状的裁定）

- **领域模型**：**一张 `work_item` 表，`kind` 为列**，`parent_id` 自引用任意深度。这是全案杠杆最大、最难回头的 schema 决定，且它走链的形状而非现有域包的形状——现有域包用三个分型接口加手工维护的子 id 数组，要装下 Review/Incident/Release 就得再加四个接口。知识**不是**一种 work kind，它是独立的页面树。
- **状态**：恰为 Owner 的七态，转移表**存在数据里**而非代码里；`done → active` 与 `cancelled → planned` 允许——**重开是常态，不是例外**。
- **标识**：不透明 ULID + 另一列人类可读键（`PROJ-123`）。现有的"内容摘要即 id"必须删除：字段相同的两条记录会碰撞并静默互相覆盖，且首次编辑后摘要即不再匹配。
- **服务面**：单一领域服务，每个产品动作是注册表里的一条，同时声明其 HTTP 路径、MCP 工具名与 UI 控件。授权在派发处检查一次，任何传输层与处理器都不重复实现。
- **MCP**：现有 `packages/mcp-server` 删除而非改造（无握手，真实客户端连不上），改用官方 SDK，同一进程两个绑定（HTTP + stdio），`tools/list` 由注册表生成。
- **身份**：全部新建。单张主体表，`kind ∈ {human, agent, service}` 只作显示与审计标签、不授予任何权限；密码走标准库 scrypt（最敏感路径上不引入原生编译模块）；MCP over HTTP 只认 PAT，故 MCP 面永远不可能超出该令牌主体在 REST 上的权限。**不做**：组、自定义角色、字段级权限、多租户、OIDC——要求一个身份提供方会让单项目在运行期依赖外部服务，与目标 5 冲突。
- **前端**：React 服务端渲染 + 具名岛屿水合，无元框架。四个岛屿各自带无 JS 回退，回退提交同一条命令。
- **编辑器**：**Markdown 为真值**，MVP 出文本域 + 工具条 + 实时预览（零编辑器依赖，且因从不解析原始 HTML，用户内容不带任何 XSS 面，也就不需要消毒库）。富编辑器登记为**有界实验**：范围＝页面编辑器，判据＝一次真实的 Owner 撰写会话，时限＝三期末，判定人＝Owner。
- **设计系统**：`pnpm pack` **四个**包（实测修正：`WorkItemRow`、`WorkSplitView`、`GatePipeline`、`RelationshipChip` 与整个 `Knowledge*` 族住在 `@tcrn/ui-domain`，不在 `ui-react`；三包方案构建不起来），tarball 连同 sha256 提交进 `vendor/`，以 `file:vendor/*.tgz` 依赖并离线安装。这同时消掉 `INC-031`：pnpm 把 `file:../` 目录依赖硬链到同一 inode，版本审计实为读同一份文件两次，永远不可能红。

## 6. 退役记录（B 裁定）：放弃了什么，以及必须配套修订什么

### 6.1 检验结论（推翻本材料作者的原始主张）

作者原持"平台器官只能搬家、不能蒸发"，理由是 workflow 侧未覆盖这些职责。该主张送对抗关后**部分成立、部分被杀**：

- **覆盖矩阵**：两个证明拆成 47 项具体检查，workflow 侧 **34 项零覆盖、10 项部分、2 项全覆盖**（全覆盖的两项都是"容器缺失即红"这一件事）。
- **workflow 侧的约束面确实比作者上一轮记账的强**：platform-doctor 现为 **21 项检查**（非记忆中的 16）且持续跑在九门名册里；引擎对已腾空地址的拒绝是**耐久自足**的（写进被腾空树自己的元数据，此后任何引擎读写在元数据咽喉点自拒），并有守卫变异证明；字节拷贝到别处因绝对 roots 绑定不可读。
- **但"没覆盖"不是疏漏，是 workflow 亲手写下的分工**（三处逐条复核）：doctor 对平台 `AGENTS.md` **只查 `## 三、分区拓扑` 标记串在不在、从不解析表格**，其注释言明这是设计（"no second roster exists for anything to drift against"）；引擎 0.9.0 发布说明原文写明恢复腾空前元数据即可让地址复活而"the engine **cannot** detect this — not 'does not currently'; **cannot**"，检测能力被明文指派到引擎之外；《依赖方向与集成边界公约》第六节**早已登记**这批器官"判的是平台的事，住在产品仓里"。
