# Security And Privacy Boundaries

The current local checkpoint stores references and posture records, not raw private payloads.

Rejected or redacted input classes include:

- credentials and token-shaped values
- private key material
- raw secret scan output
- shell history markers
- browser or keychain material
- raw source diffs
- machine-local absolute path dumps
- restricted evidence bodies

Owner-intent-required actions are modeled as pending gates. They are not executed automatically by the gateway or adapter.

The Codex adapter is dry-run only. It records intended dispatch payloads and readback models, but it does not send to live threads in this checkpoint.

Slice 2 runtime proof uses ephemeral local fixture storage and a loopback-only short-lived service. The proof scripts do not retain runtime DB files, start external queues, execute copied helpers, or store local absolute path dumps in AOS records.

Slice 3 gateway/adapter proof remains dry-run and local-only. Gateway writes require authenticated AI employee identity, active role/thread binding, project scope, write permission, idempotency, and payload safety before runtime storage. Codex Adapter outbox records are never delivered to live threads; readbacks and returns are fixture/local records only.

Slice 4 operations cockpit proof is a non-visual read-model contract. It shows gate, conference, evidence, dependency, and resource posture metadata only; it does not import raw private evidence bodies, display raw source, execute live Codex dispatch, scan/materialize resources, commit runtime operational data, or claim Product Design visual acceptance.

Slice 5 conference/AI operating-loop proof remains local-only. Conference invite outbox rows are dry-run records, linked back to conference readbacks, and never sent to live Codex threads. Work-index drill-through exposes story/assignment/gate/conference/evidence/audit metadata only; it does not mutate thread registry state, execute copied helpers, automate action items, ingest private evidence bodies, or turn Owner Intent gates into automatic operations.

Slice 6 knowledge/guide/release-note proof remains local-first and metadata-only. Documentation records may link stories, conferences, and evidence, but they do not store runtime operational content dumps, raw private evidence bodies, raw source dumps, local absolute path dumps, or publication payloads. Export, publish, canonical knowledge promotion, guide publication, and release-note closeout remain blocked without a separately routed Owner Intent/export packet.

Slice 7 dependency/license and Resource Library governance proof remains local-first and metadata-only. Dependency records and detection findings do not install, remove, update, remediate, or mutate package files. Resource records, materialization requests, manifests, and audit findings do not run scanners, ingest raw scanner output, copy binaries, materialize assets, or write product repos. Legal completion, dependency clean posture, public readiness, release readiness, Product Design final acceptance, product acceptance, and final MVP acceptance remain unclaimed.

Slice 8 materialization history/update/rollback proof remains no-execution and local-first. Materialization history, update, replacement, rollback, rollback-plan, retirement, cleanup-readback, and materialization-control index records preserve lineage and blocker metadata only. Caller-supplied true execution claims for binary transfer, materialization, update, replacement, rollback, cleanup, delete, or product-repo writes are rejected before storage. No resource binary transfer, product-repo write, scanner ingestion, rollback execution, cleanup/delete execution, release readiness, public readiness, legal completion, Product Design final acceptance, product acceptance, or final MVP acceptance is claimed.

Slice 9 docs/search and release-candidate linkage proof remains local-first and metadata-only. Docs readiness, sanitized search index, GitHub metadata, PR/CI story readiness, and release-candidate linkage records preserve review/readback posture only. Caller-supplied true publication, Git export, canonical knowledge promotion, GitHub write, release creation, CI mutation, deployment, release-readiness, public-readiness, legal-completion, dependency-clean, product-acceptance, or final-MVP-acceptance claims are rejected or fixed false before storage. No docs publication/export, canonical knowledge promotion, GitHub mutation, release creation, deployment, live Codex dispatch, scanner ingestion, resource materialization, product acceptance, or final MVP acceptance is claimed.

Slice 9B visible readiness inspection remains a static local browser target over Slice 9 metadata. It renders sanitized docs/search/release-candidate readbacks, evidence links, GitHub/PR/CI fixture metadata, dependency/resource blocker posture, and no-execution flags only. It does not ingest raw source, private evidence bodies, raw scanner output, local absolute path dumps, shell history, browser/keychain material, or auth state. It does not publish docs, export docs, promote canonical knowledge, mutate GitHub/CI, create releases, deploy services, execute live dispatch, run scanners, materialize resources, or claim Product Design final acceptance, release readiness, product acceptance, or final MVP acceptance.

Slice 10 AOS-wide Product Design surface set remains a static local evidence-stage target set. It composes sanitized readbacks from the accepted cockpit and docs/search/release anchors plus local target-set metadata. It does not ingest raw source, private evidence bodies, raw scanner output, local absolute path dumps, shell history, browser/keychain material, auth state, or product runtime data dumps. The minimal admin/access/audit shell is read-only: break-glass, owner-only gates, mutable admin CRUD, mutable audit actions, live dispatch, thread registry mutation, docs export/publication, canonical promotion, GitHub mutation, deployment, resource materialization, scanner ingestion, product-repo writes, release readiness, product acceptance, final MVP acceptance, AOS-wide Product Design acceptance, and Codex Security scan completion remain unclaimed and unavailable from this surface.

AOS 59h live-dispatch dry-run/no-send proof remains local-only. It constructs proposed dispatch envelopes and validates terminal-return observations without invoking send-message, handoff, create, fork, archive, rename, pin, successor-registration, live dispatch, thread registry mutation, generated bridge mutation, deployment/runtime actions, or Owner Intent execution. No-send proof records use redacted/count-only audit posture; raw source, raw secret scan output, raw scanner output, private evidence bodies, shell history payloads, browser/keychain material, and accepted machine-local absolute path dumps are rejected before storage.

AOS 59k Stage A live-dispatch readiness proof remains implementation/evidence hardening only. It models execution-ready envelopes, target-readback validation, terminal-return receipt validation, idempotency/replay, and duplicate-send prevention as local data. Target readbacks fail closed unless the thread id is trimmed nonblank, role id matches, canonical thread name is nonblank, readback timestamp is parseable/fresh, and the target state is eligible. Payload digests and terminal receipt checksums must use canonical `sha256:<64 hex>` format; receipt references must be nonblank redacted evidence JSON paths; prose payload snippets are rejected even when they do not match restricted-content patterns. Real live dispatch, terminal-return ingestion execution, external thread messages, thread registry mutation, generated bridge mutation, thread-management primitives, deployment/runtime execution, Owner Intent execution, Stage B readiness, product acceptance, final MVP acceptance, Codex Security scan completion, and Defensive Programming Calibration completion remain unclaimed and unavailable from this checkpoint.

AOS 59S Stage B terminal-return ingestion/readback proof remains fixture-mode implementation/evidence hardening only. It models `StageBTerminalReturnIngestionRecord` storage and readback for the already-returned Ilya terminal packet shape using synthetic/redacted fixture rows, adapter-owned in-memory records, and count/reference-only audit metadata. The real terminal turn is not ingested as product state. Exact source identity, payload digest, send count, retry limit, stop gate, immutable receipt references, all-false action booleans, idempotency, dedupe, replay, and restricted-payload checks fail closed before storage. Real ingestion execution, second send, retry, live dispatch, thread registry mutation, generated bridge mutation, thread-management primitives, deployment/runtime execution, Owner Intent execution, Stage B execution readiness, product acceptance, final MVP acceptance, Codex Security completion, and Defensive Programming Calibration completion remain unclaimed and unavailable from this checkpoint.

AOS 59Z persistent runtime storage prerequisite proof remains product-local and target-host-held. The focused command uses a route-owned temporary runtime root unless a later execution route authorizes a target-host root. It canonicalizes runtime roots through nearest-existing-ancestor realpath before containment, marker digest validation, storage, or reset. It rejects missing roots, conflicting temp/explicit root flags, source-tree roots, wrong-sibling roots, case-insensitive source-tree/wrong-sibling aliases when supported by the filesystem, symlink roots, symlink ancestors, non-empty unowned roots, stale runtime data, stale marker/root-digest mismatches, unowned cleanup, and dangerous marked source-tree reset before storage or reset. It writes only synthetic non-private operational data, proves restart/readback and backup/restore locally, resets the route-owned root, and does not transfer source, write `/srv`, start services, retain private runtime data, or claim transfer clearance, target-host proof, deployment/runtime readiness, product acceptance, final MVP acceptance, Codex Security completion, or Defensive Programming Calibration completion.
