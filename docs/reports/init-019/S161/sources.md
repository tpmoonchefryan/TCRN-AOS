# STORY-161.1 源清点与去重规则 —— 三源策展

签发:执行层 agent:fable · 2026-08-05 · D7 已裁:三源策展,首批 ≥20 卡,每卡 evidence ≥1。

## 三源

| 源 | 内容 | 候选条目数 | 取法 |
| --- | --- | --- | --- |
| **A. 自动记忆索引** | 执行层自动记忆里的平台教训(探针/判据/门/凭据/上下文/多代理等) | ~25 条 | 记忆索引逐条转卡片;**不搬原文当卡**——卡要有主张、有 evidence、可证伪 |
| **B. 链上 scope 与注解** | 各链工作项 scope 里记录的平台事实(引擎语义、仪式纪律、搬迁/权限裁定) | ~15 条 | 链上 work-show 的 advisory.scope;evidence 指回链上记录 id |
| **C. docs/reports 教训** | INIT-018 及更早报告里的缺陷与修复(INC-032/037/039/040 等) | ~12 条 | 报告文件路径;evidence 用 `evidence:<报告>` 形态 |

## 去重规则

1. **同一事实只留一张卡**:A/B/C 三源若描述同一件事(如「判据两侧必须能够不同」既在记忆也在报告),
   取**最完整 evidence 的版本**,其余条目折叠进去,不做重复卡。
2. **卡与卡之间按「主张」去重**:不是按来源去重。两张卡若主张相同(如「复核走 MCP」与「不 SSH 直驱引擎」是同一主张),
   合并;主张不同才分卡。
3. **记忆原文不直接入卡**:自动记忆是日记形态,卡要有「主张 + evidence + 可证伪」。原文只作措辞素材。
4. **evidence id 只验形状不验存在**(161.2 红线):`evidence:<…>` 形态,但人(本执行者)保证它指到真实出处。
