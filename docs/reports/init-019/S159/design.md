# STORY-159.1 端点设计 —— 座舱原生 MCP + 渲染上移(阶段二)

签发:执行层 agent:fable · 2026-08-05 · TCRN-CROSS-INIT-019 派工批次 1
> D6 已确认(MIN-061):阶段二 = 座舱服务在 VM 原生供 MCP 端点,投影与渲染上移,笔记本退为纯客户端。
> **本文是 159.2-159.4 的设计依据,先出设计再动手。**

## 目标

消除「视图新鲜度取决于笔记本醒着」的耦合(159.2),并把本机写读面都收敛到 VM(159.3)。

## 159.2 端点设计

- **宿主**:VM 座舱服务(`tcrn-aos-cockpit`,systemd 常驻)内新增原生 MCP 端点;沿用既有 loopback + SSH 隧道可达面(CONF-007 D7 绑定不动)。
- **协议**:MCP stdio(服务进程内)/或 streamable-HTTP;与 156 写面、只读面同一协议家族,客户端不必学第二套。
- **工具集**:读面(知识/work 读动词)+ 写面(单一 ceremony 工具)——把 156 的写面与 132 的读面都搬到 VM 上供,本机不再驻留 MCP 服务器进程。
- **分叉约束**:不逐字节拷贝制造第二权威(159.4 红线)——VM 服务直接读链、直接投影,本机只做渲染客户端。

## 159.2 投影与渲染上移

- `cockpit:data`(build-cockpit-data)与 web 装配从笔记本搬到 VM;投影 freshness 的真源/自身都落 VM。
- 消除「笔记本醒着才有新鲜视图」——VM 常驻重建,笔记本只 fetch。

## 159.3 本机退纯客户端

- 扩展 `local-purity:proof`:新增判据「本机不承担渲染」——本机无驻留投影装配进程。
- 本机保留:只读归档、fallback 影子链、客户端(MCP 客户端 + 浏览器)。

## 159.4 迁移与回滚

- 一次性可回退切换计划:先在 VM 起新端点(端口并存),旧 loopback 面保留;客户端配置指向 VM;
  验证后切流量;回滚 = 客户端配置指回本机旧面(不破坏任何字节)。
- **不得**用逐字节拷贝制造第二个权威——VM 服务读链真值,不是拷一份数据。

## 生效证据(159.2-159.4 完成后)

- VM 端点经 loopback+隧道可达,读面/写面工具可用;`local-purity:proof` 含「本机不承担渲染」判据绿;
  切换后一条读经 VM 端点返回与链一致;回滚后本机旧面仍可用。
